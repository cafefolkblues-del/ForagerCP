# "이 물건은 어느 구역 소속인가" — 공간 소속 문제와 기법들

_작성 2026-11-11 · 바다 2단계(섬 솟아오름 준비) 중에 부딪힌 문제_

## 1. 무슨 일이 있었나

섬이 솟아오를 때 그 구역의 땅·광물·구조물을 **한 덩어리로** 들어 올려야 했다.
처음 계획은 씬을 구역별로 다시 묶는 것이었다.

```
지금 (종류별)                 계획했던 것 (구역별)
광물/  (49개, 3구역 섞임)      Land/첫 들판/광물
구조물/(25개, 3구역 섞임)      Land/첫 들판/구조물
몬스터/                        Land/바위 지대/광물 ...
```

그런데 배치 팔레트는 새 오브젝트를 넣을 곳을 **"카테고리가 같은 첫 번째 폴더"** 로 고른다.
구역별로 묶으면 "광물" 폴더가 3개가 되고, 바위 지대에 놓은 광물이 들판 폴더로 들어간다.
그 광물은 섬이 솟을 때 따라 올라오지 않는다 — 조용히 틀리는 버그.

## 2. 왜 예상 못 했나 — 숨은 가정

> **"카테고리 하나 = 폴더 하나"** 라는 가정이 코드에 적혀 있지 않고 팔레트 안에 숨어 있었다.

하이어라키(부모-자식)는 **한 가지 축으로만** 묶을 수 있다. 종류로 묶으면 구역을 잃고, 구역으로 묶으면 종류를 잃는다.
"무엇으로 묶을지"를 바꾸면 **그 묶음을 기준으로 동작하던 도구들**(팔레트, 검사기, 저장)이 전부 영향을 받는다.

### 이런 문제를 알아차리는 신호
- "폴더/부모를 바꾸자"는 결정이 나오면 → **누가 그 부모를 찾아서 쓰는지** 먼저 검색한다 (`GetComponentInParent`, `FindObjectsByType<폴더>`, 이름 검색).
- 같은 물건을 **두 가지 기준**(종류·장소)으로 다뤄야 하면 → 하이어라키 하나로는 안 된다는 신호.
- 소속이 **위치에서 계산 가능**하면 → 소속을 따로 저장하지 않는 쪽이 대개 안전하다 (두 곳에 적으면 언젠가 어긋난다).

## 3. 이 문제를 푸는 기법들

| 기법 | 방식 | 좋은 점 | 아쉬운 점 | 쓰는 곳 |
|---|---|---|---|---|
| **A. 하이어라키로 묶기** | 구역 루트 밑에 넣는다 | 눈에 보인다, 통째로 옮기기 쉽다 | 축이 하나뿐. 도구가 구역을 알아야 한다 | 소규모, 구역이 절대 안 바뀌는 맵 |
| **B. 구역마다 씬/프리팹 분리** | 섬 = 추가 씬(Additive) 또는 프리팹 하나 | 섬 단위로 불러오기·내리기·협업 분리 | 씬 넘나드는 참조가 끊긴다, 셋업 비용 | 오픈월드 스트리밍, 섬이 많을 때 |
| **C. 공간 명부(레지스트리)로 조회** | 물건이 칸에 스스로 등록 → "이 구역 칸에 있는 것"을 묻는다 | 소속을 저장하지 않으니 어긋날 일이 없다. 새로 놓은 것도 자동 | 하이어라키에서 구역이 안 보인다 | 그리드 게임, 타일 기반 월드 |
| **D. 소속 표시(태그/ID) 찍기** | 각 물건에 `RegionId` 필드를 두고 배치 때 찍는다 | 조회가 빠르고 명시적 | 옮기면 다시 찍어야 한다 — 위치와 어긋날 수 있다 | 위치와 소속이 무관할 때(예: 퀘스트 소속) |
| **E. 청크(공간 분할)** | 월드를 고정 크기 칸 묶음으로 나누고, 청크가 단위 | 대규모에서 강함(로딩·컬링·저장) | 구역 모양과 청크 모양이 다르다 | 마인크래프트식 무한 맵 |
| **F. 물리 쿼리** | OverlapBox로 그 자리에 있는 콜라이더를 찾는다 | 코드가 짧다 | 꺼진 콜라이더(캐고 리스폰 대기 중인 광물)를 못 찾는다 | 임시 판정용 |
| **G. ECS 공유 컴포넌트** | DOTS에서 구역 ID를 SharedComponent로 두면 같은 구역끼리 메모리에 모인다 | 대량 처리 최적 | DOTS 전환 필요 | 수만 개 단위 |

## 4. 우리가 고른 것: C (공간 명부)

이미 있던 것 두 개를 엮었다.
- `GridOccupancy` — 배치물이 켜질 때 자기 칸을 스스로 등록하는 명부
- `RegionMap` — 칸 → 구역

"바위 지대 소속" = **바위 지대 칸에 등록된 배치물**. 따로 적어두지 않으므로 어긋날 수 없다.
섬이 솟는 순간에만 임시 부모 밑으로 모아 들어 올리고, 끝나면 원래 폴더로 돌려놓는다.

D(소속 ID)를 안 고른 이유: 위치로 계산되는 사실을 따로 저장하면 "옮겼는데 ID는 옛 구역" 같은 버그가 생긴다.
A·B를 안 고른 이유: 팔레트·검사기·저장이 전부 구역을 알도록 고쳐야 하고, 지금 섬은 3개뿐이다.

## 5. 기억할 것 한 줄

> **소속이 위치에서 계산되면 저장하지 말고 물어본다.
> 하이어라키는 한 축만 표현한다 — 축을 바꾸기 전에 그 축에 기대는 도구부터 찾는다.**

같은 원리로 앞서 고친 것: 체력바(몬스터가 스스로 알리게), 경험치·데미지 숫자(같은 유형, 아직 미수정).
