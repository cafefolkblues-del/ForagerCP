# 콘텐츠 작업 인계 문서

대상: 아이템·몬스터 패턴 등 콘텐츠 개발
갱신: 2026-10-16

---

## 0. 한 장 요약

**이 프로젝트에서 콘텐츠는 코드가 아니라 에셋입니다.**

광물 하나, 몬스터 하나, 상점 품목 하나를 추가하는 데 C# 파일을 여는 일은 없습니다.
유니티 에디터에서 에셋(`.asset`)을 만들고 인스펙터에서 수치를 채우면 끝입니다.
씬에 배치하는 것까지도 전용 창으로 합니다.

코드를 건드려야 하는 경우는 **"지금까지 없던 종류의 동작"이 나올 때뿐**이고,
그때도 파일 하나를 상속해서 만듭니다(4장 참고). 그 경우엔 알려주세요.

---

## 1. 툴 네 개

전부 유니티 상단 `Tools / ForagerCP` 메뉴에 있습니다.

| 메뉴 | 하는 일 | 언제 |
|---|---|---|
| **새 콘텐츠 만들기** | 광물·몬스터·구조물의 에셋 + 프리팹 + 머티리얼을 한 번에 생성 | 새 광물/몬스터를 추가할 때 가장 먼저 |
| **맵 배치** (Ctrl+Shift+M) | 씬 뷰에서 팔레트로 광물·몬스터·구조물을 칸에 찍어 배치 | 만든 것을 월드에 놓을 때 |
| **지역 편집** (Ctrl+Shift+R) | 드래그로 구역을 나누고 경계벽을 자동 생성 | 구역 작업 |
| **밸런스 표** | 모든 광물·몬스터·장비의 파생 수치(처치 타수, DPS, 분당 경험치…)를 한 표로 | 수치를 고친 뒤 확인 |
| **씬 검사** | 배선 누락·중복·칸 겹침 등 "돌려봐야 아는 문제"를 미리 잡음 | 커밋 전에 한 번 |

**새 콘텐츠 만들기**에는 "본으로 삼을 에셋" 칸이 있습니다.
기존 몬스터를 골라 값을 불러온 뒤 숫자만 바꾸면 비슷한 종류를 빠르게 찍어낼 수 있습니다.

## 2. 무엇을 어디에 만드나

에셋 생성은 프로젝트 창에서 **우클릭 → Create → ForagerCP → …** 입니다.

| 만들 것 | Create 메뉴 | 들어갈 폴더 |
|---|---|---|
| 광물 | `ForagerCP/광물` | `Assets/_Project/Items` |
| 일반 아이템 | `ForagerCP/아이템` | `Assets/_Project/Items` |
| 소모품(회복·버프 등) | `ForagerCP/소모품` | `Assets/_Project/Items` |
| 소모품 효과 | `ForagerCP/소모품 효과/…` | `Assets/_Project/Items/Effects` |
| 버프 | `ForagerCP/버프` | `Assets/_Project/Buffs` |
| 장비(무기·방어구·도구) | `ForagerCP/장비` | `Assets/_Project/Equipment` |
| 제작법 | `ForagerCP/제작법` | `Assets/_Project/Recipes` |
| 상점 품목 | `ForagerCP/상점 품목` | `Assets/_Project/Shop` |
| 상점 효과 | `ForagerCP/상점 효과/…` | `Assets/_Project/Shop/Effects` |
| 몬스터 | `ForagerCP/몬스터` | `Assets/_Project/Items` |
| 몬스터 공격 | `ForagerCP/몬스터 공격/…` | `Assets/_Project/Monsters/Attacks` |
| 지역 / 지역 조건 | `ForagerCP/지역`, `ForagerCP/지역 조건/…` | `Assets/_Project/Regions` |
| 스킬 / 스킬 효과 | `ForagerCP/스킬`, `ForagerCP/스킬 효과/…` | `Assets/_Project/Skills` |

### 자주 쓰는 구조 두 가지

**① 상점 품목 = 품목 + 효과**

**상점 품목** 에셋은 이름·가격·선행 품목만 들고 있고,
**무슨 일이 일어나는지는 효과 에셋**이 정합니다.

```
Good_Potion (상점 품목)        ← 이름 "회복약", 가격 60, 선행 없음
  └ Shop_Potion (상점 효과/아이템)  ← 회복약 1개를 인벤에 넣는다
```

효과 종류는 지금 셋입니다 — `아이템`(인벤에 넣기), `장비`(장착 교체), `가방 확장`.

**② 몬스터 = 몬스터 + 공격 목록**

**몬스터** 에셋은 체력·이동·탐지 거리만 들고 있고,
**공격은 따로 만든 에셋을 목록에 넣습니다.** 한 마리가 여러 공격을 가질 수 있습니다.

```
Monster_Slime (몬스터)          ← 체력 20, 이동 2.5, 탐지 8
  └ Attacks[0] = Attack_Slime_Melee (몬스터 공격/근접)   ← 피해 2, 사거리 1.2, 대기 1.2초
```

- 목록 **순서가 우선순위**입니다. 쓸 수 있는 것 중 위에 있는 걸 먼저 씁니다.
  원거리 몬스터는 보통 `[투사체, 근접]` 순으로 넣습니다.
- 재사용 대기 시간은 **공격마다 따로** 돕니다. 근접을 썼다고 투사체까지 잠기지 않습니다.
- `예고`(윈드업)를 0보다 크게 주면 그 시간만큼 멈췄다가 내지릅니다. 0이면 즉발입니다.

## 3. 수치 필드 읽는 법

인스펙터 필드에는 대부분 주석이 달려 있습니다. 헷갈리기 쉬운 것만 짚습니다.

**광물**
- `최대 체력`: 몇 번 때려야 깨지는지를 결정합니다. (캐는 횟수 = 체력 ÷ 채집력, 올림)
- `채집 수량`: 깨질 때 나오는 개수.
- `골드 가치`: 판매 시설에서 개당 받는 돈.
- `재등장 지연`: 깨진 뒤 다시 생기기까지의 초.

**몬스터**
- `탐지 거리`: 플레이어를 발견하는 거리.
- `복귀 거리`: 스폰 지점에서 이만큼 멀어지면 표적을 놓고 돌아갑니다.
- `경험치 보상`: **현재 꺼져 있습니다.** 몬스터 처치로는 경험치를 주지 않기로 결정됐고,
  값은 나중을 위해 남겨둔 것입니다(`CombatRewardService`의 토글로 막혀 있음).

**몬스터 공격**
- `피해` / `사거리` / `재사용 대기`
- `최소 사거리`: 이보다 가까우면 **못 씁니다.** 원거리 공격이 코앞에서 발사되는 걸 막습니다. 0이면 제한 없음.
- `예고`: 내지르기 전에 멈춰 있는 시간.
- `종류`: `Normal`이면 플레이어가 정면 방패로 막을 수 있고, `Unblockable`이면 막아도 들어갑니다.

**장비**
- `부위`(무기/방어구/도구)와 `단계`가 있습니다.
  **같은 부위에서 단계가 더 높은 것만 장착됩니다.** 단계를 잘못 주면 교체가 안 됩니다.

**제작법**
- `결과`는 `장비`와 `아이템` 중 **하나만** 채웁니다.
- `분류`가 제작대의 분류와 같아야 그 제작대에 뜹니다(현재 `Tools`).

## 4. 코딩이 필요한 순간

아래에 해당하면 코드가 한 파일 필요합니다. **직접 하실 필요 없고, 알려주시면 됩니다.**
(각각 짧은 클래스 하나이고, 추가해도 기존 에셋·씬은 그대로입니다.)

| 상황 | 필요한 것 |
|---|---|
| 지금까지 없던 **소모품 효과** (예: 해독, 순간이동) | `ConsumableEffect` 상속 |
| 지금까지 없던 **상점 효과** (예: 영구 이동속도) | `ShopEffect` 상속 |
| 지금까지 없던 **몬스터 공격** (예: 돌진, 광역) | `MonsterAttack` 상속 |
| 지금까지 없던 **지역 개방 조건** (예: 보스 처치) | `RegionRequirement` 상속 |
| 지금까지 없던 **스킬 효과** | `SkillEffect` 상속 |

반대로, **이미 있는 종류의 변형은 전부 에셋만으로 됩니다.**
"회복량이 다른 회복약", "사거리가 다른 투사체", "가격이 다른 품목"은 코딩이 아닙니다.

## 5. 반드시 지킬 것 세 가지

### ① 새 에셋을 만들면 저장 명부를 갱신합니다

`Assets/_Project/SaveCatalog.asset`을 선택 → 인스펙터의
**"프로젝트에서 다시 긁어오기"** 버튼을 누릅니다.

세이브는 에셋을 **이름으로** 찾습니다. 명부에 없으면 저장했다 불러올 때 그 아이템이 사라집니다.
새 에셋을 만든 날엔 습관처럼 한 번 눌러주세요.

### ② 에셋 **파일명**은 세이브 키입니다

파일명을 바꾸면 기존 세이브에서 그 항목이 사라집니다.
화면에 보이는 글자를 고치고 싶으면 **파일명이 아니라 `표시 이름`(`_displayName`) 필드**를 바꿉니다.
(비워두면 파일명이 그대로 화면에 나옵니다.)

### ③ 당분간 씬 파일은 건드리지 않습니다

`Assets/Scenes/SampleScene.unity`는 하나의 거대한 파일이라
두 사람이 같이 고치면 깃 충돌을 손으로 풀기가 매우 어렵습니다.

- **에셋 작업**(`.asset`, `.prefab`) → 자유롭게
- **씬 배치**(맵 배치/지역 편집 창을 쓰는 일) → 저한테 말해주세요

나중에 작업이 안 겹치게 정리되면 이 제한은 풉니다.

## 6. 작업 흐름

```
1. 시작하기 전에 받기    git pull
2. 에셋 만들고 수치 채우기
3. SaveCatalog → "프로젝트에서 다시 긁어오기"
4. Tools/ForagerCP/밸런스 표 로 수치 확인
5. Tools/ForagerCP/씬 검사 → 오류 0 확인
6. 커밋 · 푸시                git push
```

**브랜치를 따지 않고 `main`에 바로 올립니다.**

보통은 브랜치를 쓰는 게 맞지만, 유니티 프로젝트에서는 반대입니다.
에셋(`.asset`)과 씬(`.unity`)은 깃이 **자동으로 합쳐주지 못하는 파일**이라,
브랜치가 오래 살아 있을수록 나중에 합칠 때 손으로 풀 것이 늘어납니다.
**짧게 자주 올리는 쪽이 충돌이 적습니다.**

그래서 지키면 좋은 두 가지:

- **시작 전에 `git pull`** — 남이 올린 것 위에서 작업해야 합니다
- **다 끝내고 몰아서 올리지 말고, 한 덩어리가 끝날 때마다 올립니다**
  (광물 하나 만들었으면 그때 올리는 식)

커밋 메시지는 **무엇을 왜 그렇게 정했는지**를 적어주세요.
수치는 나중에 반드시 다시 건드리게 되는데, 그때 "왜 이 값이었나"가 남아 있어야 합니다.

## 7. 첫 과제: 광물 5종 교체

기획서(`상점 상품 및 구매 기획서`)가 광물을 **돌 · 철 · 은 · 금 · 수정** 다섯으로 확정했습니다.
현재 프로젝트에는 **철 · 구리 · 수정** 셋뿐입니다.

할 일:
1. `구리`를 **돌**로 바꿉니다. (단가 10·체력 30으로 최하위라 자리가 정확히 맞습니다.
   파일명을 바꾸면 세이브 키가 바뀌므로 — ②번 규칙 — **새로 만들고 옛것을 지우는 쪽**으로 갑니다. 세이브는 아직 테스트용뿐이라 괜찮습니다.)
2. **은**, **금**을 새로 만듭니다. 체력·단가는 철(60·30)과 수정(100·75) 사이로 잡고,
   밸런스 표에서 채집 시간이 완만하게 올라가는지 봅니다.
3. 도구 강화 제작법 4개의 재료를 기획서 표대로 고칩니다.

| 목표 도구 | 재료 |
|---|---|
| 철 도구 | 돌 20 · 철광석 20 |
| 은 도구 | 철광석 15 · 은광석 20 |
| 금 도구 | 은광석 15 · 금광석 20 |
| 수정 도구 | 금광석 15 · 수정 20 |

4. 배치는 하지 마시고(③번 규칙) 에셋까지만 해주시면 제가 맵에 올리겠습니다.

**이 작업이 뒤의 거의 전부를 막고 있습니다** — 도구 강화 재료, 판매 단가, 구역별 광물 배치가
전부 광물 라인업이 정해져야 진행됩니다. 그래서 첫 과제로 드립니다.

## 8. 막히면

- 인스펙터 필드가 무슨 뜻인지 모르겠다 → 해당 스크립트의 주석에 거의 다 적혀 있습니다.
  그래도 모르겠으면 물어봐 주세요. 주석이 부족한 것이면 제가 보강하겠습니다.
- 에셋을 만들었는데 게임에 안 나온다 → ①번(명부 갱신)을 먼저 확인.
- 씬 검사에 경고가 뜬다 → 내용을 그대로 보내주시면 됩니다. 대부분 배선 한 칸입니다.
- "이건 코딩이 필요한 것 같다" → 4장 표와 대조해보시고, 애매하면 그냥 물어봐 주세요.

함께 보면 좋은 문서: `docs/SPEC_SYNC.md` — 기획서와 현재 구현의 차이를 항목별로 정리한 표입니다.
무엇이 이미 되어 있고 무엇이 아직인지 여기서 확인할 수 있습니다.
