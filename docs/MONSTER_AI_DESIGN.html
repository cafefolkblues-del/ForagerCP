몬스터 상태머신 재설계

지금은 모든 몹이 MonsterAI.FixedUpdate 한 곳의 판단을 같이 써요. 몹별로 이동·후퇴·공격 패턴이 달라질 예정이라, 공통 규칙은 한 곳에 묶고 몹마다 다를 자리는 에셋으로 갈아 끼우는 구조로 바꾸려는 설계안이에요. 아직 코드에 반영하지 않았어요.

1한 장 요약

결정내용
상태 구현무상태 ScriptableObject 에셋. 동작과 수치만 들고, 진행 값(타이머·방향·예고 중인 공격)은 몬스터 컴포넌트의 MonsterMemory가 들어요
전이상태가 다음 상태를 정해요. 다만 다음 상태를 에셋으로 직접 가리키지 않고 칸 이름(StateId.Recover 등)으로 돌려줘요. 그 칸에 무엇이 들어갈지는 몹의 패턴 에셋이 정해요
공통 (변경 금지)실행기, 방해 처리(경직·넉백·막힘), 어그로(탐지·구역·끈·초기화), 한 걸음 이동, 쿨다운 타이머
높은 수준의 빈칸추적 · 예고 · 빈틈 · 쿨다운 대기 · 후퇴. 칸마다 추상 클래스가 있고 기본 동작이 들어 있어요(virtual). 다른 몹만 덮어써요
낮은 수준의 묶음MonsterPattern 에셋. "추적 칸에는 이것, 후퇴 칸에는 저것"만 고르는 가벼운 조립표예요
그대로MonsterAttack(공격 한 번의 동작). 돌진 같은 이동형 공격만 실행기에 이동을 부탁하는 길을 정리해요
넉백 수치MonsterDefinition으로 옮겨요. 밀어내는 동작은 Knockback 컴포넌트에 그대로 둬요(플레이어도 같이 써요)
범위몹 4종(돌무더기·투척꾼·돌진수·골렘), 전투 초기화 포함, 보스는 자리만. 슬라임 2종은 제외(정리 대상)
참고한 기존 구조 추상 SO 목록 패턴은 이 프로젝트에서 이미 다섯 곳이 써요(MonsterAttack, ConsumableEffect, RegionRequirement, ShopEffect, SkillEffect). 방해 처리 층은 플레이어 쪽 PlayerActionState(넉백 > 경직 > 대시 > 방패 > 이동 우선순위를 한 곳에서 중재)와 같은 역할이에요. 새 구조는 이 두 틀을 몬스터에 그대로 가져와요.

2층 구조 — 무엇이 공통이고 무엇이 몹별인가

위로 갈수록 모든 몹이 똑같고, 아래로 갈수록 몹마다 달라요. 위층은 아래층을 부르지만 아래층은 위층의 규칙을 바꿀 수 없어요.

층바뀌는 단위누가 고치나왜 이 층인가
① 공통게임 전체프로그래머, 드물게여기가 몹마다 다르면 "맞으면 예고가 끊긴다" 같은 확정 규칙이 몹마다 어긋나요. 지금 누더기의 원인이 이 규칙들이 판단 순서 안에 섞여 있던 것이에요
② 빈칸상태 구현 하나프로그래머, 새 행동이 필요할 때모든 몹에 반드시 있지만 몹마다 다를 수 있는 자리예요. 기본 동작을 넣어 두어 대부분의 몹은 손대지 않아요
③ 묶음몹 한 종류디자이너, 에셋만몹 종류 = 상태 구현 + 공격 + 수치의 조합. 새 몹을 만들 때 코드를 안 열어요
④ 공격공격 한 번지금과 같음이미 잘 갈라져 있어요

3전체 상태 흐름

상태는 세 종류예요. 공통 상태(실행기가 직접 들고 있음), 빈칸 상태(몹별 구현을 갈아 끼움), 공격 동작 상태(공격 에셋이 진행을 맡음).

  Return --> Chase : 어그로 획득

누가 전이를 정하나

전이정하는 곳이유
전투 안의 흐름 (추적 → 예고 → 빈틈 …)각 상태의 Tick이 칸 이름을 돌려줌합의한 방식. 몹마다 흐름을 바꾸고 싶으면 그 칸의 구현을 덮어쓰면 돼요
맞음 → Stagger, 막힘 → Recover실행기 (방해 처리)상태마다 맡기면 하나만 빠뜨려도 "맞아도 공격이 나가는" 버그가 생겨요
어그로 잃음 → Return, 획득 → Chase실행기 (어그로)"다른 구역 플레이어는 표적이 아니다"는 버그 수정에서 나온 게임 규칙이라 몹이 바꾸면 안 돼요
Return → Idle (집 도착)Return 상태공통 상태라 몹별 차이 없음. "집에 닿을 때까지 유지"라 지금의 끈 경계 진동이 사라져요

4한 프레임에 일어나는 일

지금의 110줄짜리 if 사다리가 아래 다섯 단계로 줄어요. 단계 2~3이 공통 규칙이고, 몹별 행동은 단계 4에서만 일어나요.

flowchart TD
  T0([MonsterBrain.FixedUpdate]) --> T1["1. 가드
죽음 · 표적 없음 → Idle, 낙하 → 집으로"]
  T1 --> T2["2. 방해 처리
경직 · 넉백 중이면 Stagger 유지, 상태 실행 안 함"]
  T2 --> T3["3. 어그로
탐지 · 구역 · 끈 검사 → 잃으면 Return, 얻으면 Chase"]
  T3 --> T4["4. 지금 칸의 상태 실행
next = 상태.Tick(ctx)"]
  T4 --> T5["5. 전환
next가 다르면 Exit → Enter → StateChanged"]
  EV1(["Monster.Damaged"]) -.-> T2
  EV2(["PlayerHealth.Blocked"]) -.-> T2

상태 하나가 받는 것 (MonsterContext)

ctx.Memory    // 이 몬스터의 진행 값 (타이머, 예고 중인 공격, 후퇴 방향 …)
ctx.Motor     // 한 걸음 이동, 회전 — 위치는 반드시 이걸로만 옮긴다
ctx.Aggro     // 표적, 거리, 같은 구역인지
ctx.Attacks   // 쓸 수 있는 공격 고르기, 쿨다운 확인 — 쿨다운 타이머는 여기만 쓴다
ctx.Definition // 수치
ctx.Now       // 시간. Time.time을 직접 부르지 않는다 (창 열면 정지 대비)

상태는 이것만 보고 일해요. 상태 에셋 자신은 아무 값도 기억하지 않아요(무상태).

칸 이름 (enum StateId)

칸종류구현은 어디서
Idle, Return, Stagger공통실행기 안에 고정. 패턴 에셋에 칸이 없어요
Chase, Windup, Recover, CooldownWait빈칸 (필수)패턴 에셋. 비우면 기본 구현 에셋을 써요
Retreat빈칸 (선택)패턴 에셋. 비우면 후퇴하지 않아요(Chase가 Retreat를 돌려줘도 무시하고 Chase 유지)
AttackMotion공격 동작지금 내지른 공격 에셋의 TickMotion

6클래스별 책임

"하는 일"과 함께 "하지 않는 일"을 적었어요. 책임이 섞이는 걸 막는 건 주로 후자예요.

클래스하는 일하지 않는 일
MonsterBrain
컴포넌트 · 지금 MonsterAI 자리		매 프레임 단계 1~5 실행, 칸 이름 → 구현 찾기, 전환 시 Exit/Enter 호출, StateChanged·Telegraphing 이벤트, 이벤트 구독(피격·막힘)추적 방식, 후퇴 방식, 공격 고르는 규칙을 몰라요. 몹 이름으로 분기하지 않아요
MonsterMemory이 몬스터의 진행 값 보관. Clear()로 한 번에 초기화판단하지 않아요. 값만 들어요
MonsterAggro표적 찾기, 탐지 거리·같은 구역·끈 판정, 어그로 초기화(표적 놓기, 진행 값 비우기)이동하지 않아요. 복귀 이동은 Return 상태가 Motor로 해요
MonsterMotor한 걸음 이동(MovePosition + fixedDeltaTime), 회전, 구역 밖으로 나가는 걸음 거부, 넉백 중 이동 거부어디로 갈지 정하지 않아요
Knockback
기존 컴포넌트		밀어내기 동작. 세기·시간은 MonsterDefinition에서 받아요몬스터 전용이 아니에요(플레이어 공용)
MonsterState 계열
SO		칸 하나의 행동. Motor로 움직이고, Attacks로 고르고, 다음 칸 이름을 돌려줘요값을 기억하지 않아요(Memory에 적어요). 위치를 직접 바꾸지 않아요. 경직·어그로 판단을 하지 않아요
MonsterPattern
SO		칸마다 어떤 구현을 쓸지 고르는 조립표로직이 없어요. 수치도 없어요(수치는 상태 에셋이나 Definition에)
MonsterDefinition
SO · 기존		몹 종류 한 개 = 수치 + 패턴 + 공격 목록 + 넉백·경직 값진행 값을 들지 않아요
MonsterAttack
SO · 기존		쓸 수 있는지, 내지르는 순간 무엇을 하는지. 이동형이면 TickMotion으로 매 프레임 "이번엔 이만큼"을 말해요몸을 직접 옮기지 않아요(Motor에 부탁). 쿨다운을 직접 세지 않아요
Monster
기존		체력, 사망, 재등장, 피격 이벤트바뀌지 않아요

7판단 이유

왜 상태를 SO 에셋으로 만드나

  • 몹 조합을 디자이너가 인스펙터에서 바꿀 수 있어요. "돌무더기도 거리 유지형 추적으로 바꿔 보자"가 코드 수정 없이 에셋 칸 하나로 끝나요.
  • 이 프로젝트가 이미 쓰는 틀이에요. 추상 SO 목록이 다섯 곳에 있어서 팀원이 한 번 익히면 다른 곳도 같은 모양으로 읽어요.
  • 상태의 수치를 상태 에셋에 둘 수 있어요. 예: "거리 유지형 추적"의 유지 거리. 몹 수치(MonsterDefinition)가 모든 상태의 수치를 떠안지 않아도 돼요.

왜 무상태여야 하나

SO 에셋은 같은 종류의 몬스터 전부가 하나를 공유해요. 상태 에셋 안에 "예고 끝 시각"을 적으면 돌무더기 다섯 마리가 시계 하나를 나눠 쓰게 되고, 플레이 모드에서 바뀐 값이 에셋 파일에 저장돼 다음 플레이까지 따라와요(이 함정은 이미 한 번 밟았어요, CODING_GUIDE.md 1장). 그래서 진행 값은 몬스터마다 따로 있는 MonsterMemory에 적어요. "정의는 에셋, 진행은 컴포넌트" 규칙 그대로예요.

왜 다음 상태를 "칸 이름"으로 돌려주나

  • 상태가 다음을 정한다(합의)와 몹별로 구현을 갈아 끼운다(층 구조)를 함께 살리려면 이 방법뿐이에요. 상태가 다음 상태 에셋을 직접 가리키면, 예고 에셋이 "돌무더기용 빈틈 에셋"을 박아 두게 되어 같은 예고를 다른 몹에 못 써요.
  • 에셋끼리 서로 가리키는 고리(추적 → 예고 → 빈틈 → 추적)가 생기지 않아요. 고리가 있으면 하나를 지울 때 어디가 끊기는지 찾기 어려워요.
  • 칸 이름이 enum 하나에 모여 있어서 "이 몹이 어떤 상태를 오갈 수 있나"를 한 곳에서 읽을 수 있어요.

왜 칸마다 추상 클래스를 따로 두나 (MonsterState 하나로 끝내지 않고)

  • 잘못 끼우는 걸 인스펙터가 막아요. 패턴 에셋의 추적 칸은 타입이 ChaseState라서 빈틈 에셋을 끌어다 놓을 수 없어요.
  • 칸마다 기본 동작이 달라요. 추적의 기본은 "직선 접근", 빈틈의 기본은 "멈춰서 바라보기". 이 기본값을 칸의 추상 클래스에 넣어 두면, 새 구현은 다른 부분만 덮어써요.
  • 칸 추상 클래스에 그 칸이 지켜야 할 규칙을 넣을 수 있어요. 예: WindupState는 Enter에서 항상 Telegraphing을 쏘고, 하위 클래스는 이걸 끌 수 없어요.

왜 abstract가 아니라 virtual(기본 동작 있음)인가

몹 4종을 지금 코드로 보면 예고·빈틈·쿨다운 대기는 넷 다 "멈춰서 바라보기"예요. 전부 비워 두면 같은 코드를 네 번 쓰게 돼요. 기본 동작을 두고 다른 몹만 덮어쓰면, 새 몹 대부분은 상태 코드를 한 줄도 안 써요. 단 Tick은 칸마다 반드시 다음을 정해야 해서 MonsterState에서는 abstract이고, 칸 추상 클래스가 기본 구현을 채워요.

왜 경직·막힘·어그로는 상태에 맡기지 않나

"상태가 다음을 정한다"를 여기까지 넓히면, 모든 상태 구현이 "맞았나? 막혔나? 표적이 다른 구역인가?"를 각자 확인해야 해요. 하나만 빠뜨려도 "맞아도 공격이 나간다", "벽 너머로 쫓아온다" 같은 이미 고친 버그가 그 몹에서만 되살아나요. 플레이어 쪽 PlayerActionState가 같은 이유로 우선순위를 한 곳에서 중재해요.

왜 공통 부품을 "어그로 초기화" 하나보다 넓게 잡나

  • 한 걸음 이동 (Motor): 어디로 갈지는 몹마다 달라도, 한 걸음 옮기는 방법(MovePosition, fixedDeltaTime, 넉백 중 양보, 구역 밖 거부)은 같아야 구조물을 뚫거나 밀림이 상쇄되는 버그가 안 생겨요.
  • 쿨다운 타이머: "공격마다 따로, 내지른 순간부터"는 확정 규칙이에요. 쿨다운 동안 무엇을 할지는 몹별(CooldownWait 칸)이지만, 시간을 세는 방법은 공통이에요.

왜 돌진을 실행기에서 공격 에셋으로 옮기나

지금은 돌진 데이터 7개와 TickLunge가 MonsterAI 안에 있어요. 이동형 공격이 늘 때마다(보스의 도약, 회전 공격 등) 실행기가 커져요. 새 구조에서는 공격 에셋이 TickMotion으로 "이번 프레임엔 이 방향으로 이만큼"을 말하고, 실제 이동은 Motor가 해요. 위치를 쥐는 곳은 여전히 하나이고, 진행 값은 Memory에 있어요.

왜 넉백 "수치"만 Definition으로 옮기나

Knockback 컴포넌트는 플레이어도 같이 써요. 동작까지 옮기면 플레이어용이 따로 생겨요. 몹마다 다른 건 세기와 시간뿐이니 그 값만 Definition에서 넣어 줘요. 경직 시간은 "넉백보다 길어야 한다"는 확정 규칙에 묶여 있어서 같이 옮기고, 넉백보다 짧게 넣으면 검사 도구가 경고하게 해요.

첫 단계는 "지금 동작을 그대로 재현"이 목표라 대부분 기본 구현이에요. 오른쪽 열이 앞으로 몹별로 갈라질 자리예요.

11새 구조에서도 지킬 규칙

지금 코드의 주석과 확정 기획에서 모은 것이에요. 구조를 바꾼 뒤 플레이 모드에서 하나씩 확인하는 회귀 체크리스트로 써요. 오른쪽 열은 새 구조에서 이 규칙을 지키는 곳이에요.

#규칙지키는 곳확인 방법
1위치는 한 곳만 쥔다. 넉백 중엔 이동하지 않고, 공격 에셋은 몸을 직접 옮기지 않는다Motor맞으면 뒤로 밀리는지
2피격 시 경직, 예고·돌진 취소. 경직은 넉백보다 길다방해 처리 + Definition 검사예고 중에 때리면 공격이 안 나오는지
3죽는 타격도 예고를 끊는다방해 처리 (Damaged가 사망보다 먼저)예고 중 막타
4예고 중엔 제자리, 표적만 바라본다WindupState 기본 동작예고 중 옆으로 피해지는지
5근접은 내지르는 순간 사거리를 다시 본다RubbleSwingAttack · GolemSlamAttack4번과 함께
6쿨다운은 공격마다 따로, 내지른 순간부터쿨다운 타이머 (공통)골렘: 내려치기 쿨 중에도 접촉 피해
7빈틈 중엔 이동·다른 공격 없음RecoverState 기본 동작돌무더기 휘두른 직후 접촉 피해 없음
8방패에 막히면 StaggerWhenBlocked만큼 멈춘다방해 처리 → Recover 강제막은 뒤 멈추는지
9공격 우선순위 = 에셋 목록 순서공격 고르기 (공통)목록 순서를 바꾸면 행동이 바뀌는지
10사거리 안인데 쓸 공격이 없으면 더 다가가지 않는다CooldownWaitState 기본 동작투척꾼이 쏜 뒤 다가오지 않는지
11다른 구역의 플레이어는 표적이 아니다 (구획 밖 몹은 예외)Aggro경계벽 너머에서 안 쫓아오는지
12후퇴로 자기 구역을 벗어나지 않는다Motor (구역 밖 걸음 거부)투척꾼을 벽 쪽으로 몰기
13돌진은 예고 끝 방향으로 고정, 한 번만 맞히고, 벽에서 멈춘다ChargerDashAttack.TickMotion예고 중 옆으로 피하면 빗나가는지
14자기 구역은 Start에서 한 번에 잡지 않는다 (값이 설 때까지 다시 묻기)Aggro구역 안 몹이 정상적으로 쫓는지
15이동은 FixedUpdate + MovePosition + fixedDeltaTimeMotor구조물을 안 뚫는지
16예고 시작 시 Telegraphing, 돌진 시작 시 LungedWindupState 추상 클래스, 실행기이벤트에 임시 로그

12아직 정하지 않은 것

지금 코드를 읽다가 찾은 동작 문제와 설계 중 생긴 질문이에요. 첫 단계(구조만 바꾸기)에서는 지금 동작을 그대로 재현하고, 아래는 기획 확인 뒤 하나씩 정해요.

질문지금 동작새 구조에서 바꾸려면
돌진 뒤 빈틈은 언제부터 세나?내지른 순간부터 세서, 돌진(약 0.45초) 동안 빈틈이 같이 깎여요. 돌진수 실제 빈틈 ≈ 0.75초AttackMotion이 끝나고 Recover에 들어갈 때부터 세면 돼요. 흐름상 이쪽이 자연스러워요
구석에 몰린 투척꾼은 무엇을 하나?물러나지도 쏘지도 못하고 제자리에 서 있어요투척꾼 후퇴 구현에서 "막히면 옆으로" 또는 "근접 공격 칸 추가"
투사체를 방패로 막으면 투척꾼도 멈추나?안 멈춰요. 막힘 판정이 "내 자식 오브젝트인가"로 보는데 탄은 자식이 아니에요투사체가 쏜 몬스터를 따로 들고 다니게 하면 멈추게 할 수 있어요
경직 시간은 직접 넣나, 넉백에서 계산하나?모든 몹 0.22초 고정Definition에 직접 넣고 "넉백보다 짧으면 경고" (제안) 또는 "넉백 + 여유"로 계산
경직으로 무한히 묶을 수 있는데 괜찮나?맞을 때마다 예고가 취소되고 쿨다운은 안 써서, 계속 때리면 몬스터가 영영 못 때려요(확정 스펙의 결과)보스 슈퍼아머 자리(10장)로 예외만 처리
재등장을 어떻게 표현하나?구역 몹 에셋은 RespawnDelay = 99999, 슬라임은 0. "없음"이 두 가지"재등장 안 함"을 체크 상자 하나로. 전투 초기화와 별개

13옮기는 순서

구조 변경과 동작 변경을 한 커밋에 섞지 않는 것이 핵심이에요. 섞으면 무엇이 깨뜨렸는지 찾기 어려워요.

  1. 기준 기록: 11장 체크리스트를 지금 코드로 한 번 돌려 결과를 적어 둬요(가능하면 녹화).
  2. 공통 부품 떼어 내기: MonsterMemory, MonsterMotor, MonsterAggro를 MonsterAI 안에서 분리해요. 동작 변화 없음. 체크리스트 → 커밋.
  3. 상태 뼈대: StateId, MonsterState, 칸 추상 클래스 5개, 기본 구현 에셋, MonsterPattern. 실행기를 다섯 단계로 바꿔요. 몹 4종 패턴 에셋 연결. 체크리스트 → 커밋.
  4. 돌진을 공격 에셋으로: TickMotion 도입, MonsterAI의 돌진 필드 제거. 체크리스트 13번 중점 → 커밋.
  5. 넉백·경직 수치를 Definition으로: 지금 값 그대로 옮기고 씬 검사에 경고 추가 → 커밋.
  6. 전투 초기화: ResetCombat과 구역 쪽 호출(TODO 21·22와 함께).
  7. 12장 질문을 하나씩: 기획 답을 받은 것부터, 질문 하나에 커밋 하나.
  8. 몹별 패턴 갈라내기: 기본 구현 대신 몹 전용 구현 에셋을 하나씩.
