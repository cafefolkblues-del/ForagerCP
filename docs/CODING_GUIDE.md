# 코딩 유의사항 — 몬스터 편

대상: 이 레포에서 처음 코드를 쓰는 사람 (특히 몬스터 행동)
갱신: 2026-10-16

> 이 문서는 **"어떻게 쓰는가"** 입니다.
> **"왜 그렇게 짰는가"** 는 `docs/ARCHITECTURE.md`에, **"무엇이 확정인가"** 는 `docs/DECISIONS.md`에 있습니다.
> 코딩 없이 되는 작업(에셋)은 `docs/CONTENT_HANDOFF.md`를 먼저 보세요.

---

## 0. 가장 중요한 원칙 하나

**새 몬스터를 만드는 일은 대부분 코딩이 아닙니다.**

기획이 세운 방침이 "구역마다 새 몬스터가 아니라, **같은 몬스터의 강화판을 색만 바꿔 돌려쓴다**"입니다.
돌무더기는 1·2·3·5구역에 전부 나오고, 체력과 피해만 다릅니다.

그래서 코드를 쓰기 전에 **먼저 물어야 할 질문**:

> "이건 지금 있는 공격의 **수치만 다른 것**인가, **동작 자체가 다른 것**인가?"

- 수치만 다르다 → **에셋만 만듭니다. 코드 금지.**
- 동작이 다르다 → `MonsterAttack`을 상속한 클래스 **하나**를 만듭니다.

이 선을 넘으면 비슷한 코드가 몬스터 수만큼 생기고, 밸런스를 고칠 때마다 코드를 고치게 됩니다.

## 1. 몬스터는 어떤 부품으로 되어 있나

한 마리는 **컴포넌트 3개 + 에셋 2종류**로 돌아갑니다.

| 것 | 역할 | 런타임 상태를 갖나 |
|---|---|---|
| `MonsterDefinition` (에셋) | 체력·이동속도·탐지거리 등 **수치** | ✗ 절대 안 됨 |
| `MonsterAttack` (에셋) | 공격 하나의 수치와 **무슨 일이 일어나는지** | ✗ 절대 안 됨 |
| `Monster` (컴포넌트) | 체력, 생사, 피격, 재등장 | ○ |
| `MonsterAI` (컴포넌트) | 상태 전이, 이동, 어떤 공격을 쓸지 고르기 | ○ |
| `Knockback` (컴포넌트) | 맞았을 때 밀려나는 동안의 **위치** | ○ |

**에셋(ScriptableObject)에 런타임 상태를 넣으면 안 됩니다.**
에셋은 같은 종류의 모든 몬스터가 **공유**합니다. 슬라임 다섯 마리가 같은 에셋 하나를 봅니다.
거기에 "지금 쿨다운이 얼마 남았나"를 적으면 다섯 마리가 한 타이머를 나눠 쓰게 되고,
더 나쁜 건 **플레이 모드에서 바꾼 값이 에셋 파일에 저장돼 다음 플레이까지 따라온다**는 겁니다.
(이 함정은 이미 한 번 밟았습니다.)

→ 수치는 에셋, 진행은 컴포넌트. 예외 없습니다.

## 2. 한 프레임에 무슨 일이 일어나나

몬스터는 **실행기(`MonsterAI`) 하나 + 칸마다 갈아 끼우는 상태 에셋**으로 돕니다.
전체 그림은 `docs/MONSTER_AI_DESIGN.html` 3·4장에 있고, 여기는 코드를 고칠 때 알아야 할 것만 적습니다.

`MonsterAI.FixedUpdate()`는 매 프레임 다섯 단계를 돕니다.

```
1. 가드      — 죽었나 / 표적이 없나 → Idle,  바닥 아래로 빠졌나 → 스폰 자리로
2. 방해 처리 — 돌진 중 → AttackMotion,  경직·넉백 중 → Stagger(아무것도 안 함),
               방패에 막혀 빈틈이 늘었다 → Recover
3. 어그로    — 탐지 밖·다른 구역·끈 초과 → Return(집이면 Idle),  다시 보이면 → Chase
               (Return은 집에 닿을 때까지 유지하며 초당 30% 회복 — 표적이 다시 보여도 돌아간다)
               (예고·빈틈·돌진 중에는 미룬다 — 휘두르다 말고 돌아가지 않는다)
4. 상태 실행 — 지금 칸의 상태 에셋이 일하고, 다음 칸 이름(StateId)을 돌려준다
5. 전환      — 칸이 바뀌면 Exit → Enter → StateChanged, 바뀐 칸을 같은 프레임에 이어서 실행
```

몹마다 다른 행동은 **4단계에서만** 일어납니다. 칸 이름과 구현은 이렇게 짝지어집니다.

| 칸 (`StateId`) | 누가 맡나 | 기본 구현 |
|---|---|---|
| `Idle`, `Return`, `Stagger`, `AttackMotion` | 실행기 (몹별로 못 바꿈) | — |
| `Chase` | 패턴의 추적 칸 (`ChaseState` 상속) | `ChaseStraight` — 후퇴 → 공격 → 대기 → 직선 접근 순으로 정함 |
| `Windup` | 예고 칸 (`WindupState`) | `WindupStill` — 제자리에서 바라보다 내지름 |
| `Recover` | 빈틈 칸 (`RecoverState`) | `RecoverStill` — 제자리 |
| `CooldownWait` | 쿨다운 대기 칸 (`CooldownWaitState`) | `CooldownWaitHold` — 제자리 |
| `Retreat` | 후퇴 칸 (선택, `RetreatState`) | `RetreatBackAway` — 구역 안에서 뒤로. 비우면 후퇴 안 함 |

어떤 구현을 쓸지는 몹 정의(`MonsterDefinition`)의 **패턴 에셋**(`MonsterPattern`)이 정합니다.
구역별 강화판(R1~R5)은 같은 패턴을 씁니다.

### 꼭 알아야 할 것 넷

**① 2·3단계는 상태가 하지 않습니다.**
맞았는지, 막혔는지, 표적이 벽 너머인지는 실행기가 먼저 가로챕니다.
상태 코드에서 이걸 다시 묻지 마세요. 상태마다 따로 물으면 하나만 빠뜨려도 이미 고친 버그가 그 몹에서만 되살아납니다.

**② 상태 에셋에 값을 적지 않습니다.**
상태 에셋은 같은 종류의 몬스터 전부가 공유합니다. 타이머·방향 같은 진행 값은 `ctx.Memory`에 적습니다.

**③ 몸은 `ctx.Motor`로만 옮깁니다.**
넉백 중에는 실행기가 상태를 아예 실행하지 않으므로, 상태가 `Motor`로만 움직이면 밀림이 상쇄될 일이 없습니다.
예고 중에는 움직이지 않고, 내지르는 순간 사거리를 다시 봅니다(피했는데 맞으면 예고가 신호가 아니게 됩니다).

**④ 쿨다운 중이라고 더 다가가지 않습니다.**
사거리 안인데 쓸 공격이 없으면 `CooldownWait`로 갑니다. 이게 없으면 원거리 몬스터가 쏘고 나서 코앞까지 붙습니다.
쿨다운 시간은 공통(`ctx.Memory.ReadyAt`)이 세고, 상태는 "기다리는 동안 무엇을 할지"만 정합니다.

## 3. 공격 하나 추가하기

공격 클래스는 **몹별로 하나씩** 둡니다 — `RubbleSwingAttack`(돌무더기 휘두르기), `GolemSlamAttack`(골렘 내려치기),
`ThrowerShotAttack`(투척꾼 투사체), `ChargerDashAttack`(돌진수 돌진). 공용은 `ContactAttack`(몸통 접촉) 하나뿐입니다.
"근접" 같은 공용 이름으로 묶으면 한 몹을 고칠 때 다른 몹까지 같이 바뀌기 때문입니다.

아직 없는 것은 **보스의 원형 범위 공격**(기획서 5구역 "붉은 내려찍기")입니다.
그걸 예로 듭니다. 파일은 하나입니다 —
`Assets/_Project/Scripts/World/Monsters/Attacks/BossSmashAttack.cs`

```csharp
using UnityEngine;

namespace ForagerCP
{
    /// 예고 뒤 자기 주변 원형으로 때린다. 보스의 붉은 내려찍기가 쓴다.
    [CreateAssetMenu(menuName = "ForagerCP/몬스터 공격/범위", fileName = "Attack_Boss_Smash")]
    public class BossSmashAttack : MonsterAttack
    {
        [Header("범위")]
        [SerializeField] float _radius = 4f;

        public override void Execute(in MonsterAttackContext context)
        {
            // 범위 안의 것을 한 번씩만 때린다
        }
    }
}
```

> 이미 만들어진 공격 클래스를 **먼저 읽어보세요.** 특히 `RubbleSwingAttack`이 짧고,
> 아래 다섯 가지 규칙이 전부 들어 있어 본으로 삼기 좋습니다.

### 베껴야 할 모양 다섯 가지

**① `[CreateAssetMenu]`를 답니다.** 이게 있어야 디자이너가 Create 메뉴에서 에셋을 만들 수 있습니다.
메뉴 경로는 기존 것과 같은 묶음(`ForagerCP/몬스터 공격/…`)에 넣습니다.

**② 수치는 전부 `[SerializeField]`입니다.** 탄속 9, 범위 4 같은 숫자를 코드에 박으면
밸런스를 고칠 때마다 당신을 불러야 합니다. 피해·사거리·쿨다운·예고는 부모가 이미 갖고 있으니
**자기만의 수치만** 추가합니다.

**③ `Execute`는 "내지르는 그 순간"에 한 번 불립니다.** 예고 대기는 실행기가 이미 했습니다.
여러 프레임에 걸쳐 몸을 쓰는 공격(돌진·도약)은 ⑤를 봅니다.

**④ 쓸 수 없는 조건이 있으면 `CanUse`를 덮습니다.**
```csharp
public override bool CanUse(in MonsterAttackContext context)
    => _prefab != null && base.CanUse(context);   // ThrowerShotAttack의 실제 코드
```
`base.CanUse`를 꼭 부릅니다. 안 부르면 사거리 판정이 통째로 사라집니다.

**⑤ 몸을 쓰는 공격은 `HasMotion` + `TickMotion` 자리를 씁니다.**
`HasMotion`을 `true`로 두면 내지른 뒤 실행기가 `AttackMotion` 칸에서 끝날 때까지 매 프레임 `TickMotion`을 부릅니다.
```csharp
public override bool HasMotion => true;

public override bool TickMotion(MonsterContext ctx)
{
    // 몸은 ctx.Motor로만, 진행 값(방향·남은 거리)은 ctx.Memory에. 끝났으면 false.
}
```
`transform`이나 `Rigidbody`를 직접 건드리면 위치를 쥐는 곳이 둘이 되어 넉백·경직과 섞입니다(5장 ① 참고).
맞거나 막히면 실행기가 먼저 끊으므로 `TickMotion` 안에서 묻지 않습니다.
지금 이 자리를 쓰는 공격은 없습니다(임시 돌진은 폐기, `ChargerDashAttack`은 빈 자리).

### 다 쓰고 나면

새 `.cs`는 유니티가 컴파일을 끝내야 Create 메뉴에 뜹니다.
안 뜨면 `Assets → Refresh`(Ctrl+R) 한 번, 그래도 안 뜨면 **콘솔에 컴파일 오류**가 있는 겁니다.

## 4. 이건 쓰고, 이건 쓰지 마세요

이 표가 이 문서에서 가장 자주 보게 될 부분입니다.

| 하려는 일 | 쓸 것 | 쓰지 말 것 | 왜 |
|---|---|---|---|
| 몬스터 이동 | `_body.MovePosition(...)` | `transform.position +=` | 직접 옮기면 **콜라이더를 뚫습니다**. 플레이어 대시가 광물을 뚫던 버그가 이것이었습니다 |
| 이동·물리 처리 | `FixedUpdate()` | `Update()` | 물리는 고정 간격으로 돕니다. `Update`에서 밀면 프레임레이트에 따라 속도가 달라집니다 |
| `FixedUpdate` 안의 시간 | `Time.fixedDeltaTime` | `Time.deltaTime` | 틀린 값이 들어가 속도가 미묘하게 어긋납니다 |
| 다른 컴포넌트 참조 | `Awake()`에서 한 번 캐시 | 매 프레임 `GetComponent` | 프레임마다 찾으면 느립니다 |
| 씬에서 뭔가 찾기 | `Start()`에서 한 번 | 매 프레임 `FindObjectsByType` | 위와 같은 이유로, 훨씬 더 느립니다 |
| 이벤트 구독 | `OnEnable` / `OnDisable` **쌍** | `Awake`에서만 구독 | 짝이 안 맞으면 꺼진 오브젝트가 계속 이벤트를 받습니다 |
| 풀에서 재사용되는 것 초기화 | `IPooled`의 `OnSpawnedFromPool` | `Awake` / `Start` | 풀은 오브젝트를 **파괴하지 않습니다**. `Awake`는 처음 한 번만 돕니다 |
| 불러오기 중에 오브젝트 제거 | `DestroyImmediate` | `Destroy` | `Destroy`는 프레임 끝에 돕니다. 그 사이 복원이 새로 만들면 **두 배로 늘어납니다** |
| 밸런스 숫자 | `[SerializeField]` | 코드에 상수로 박기 | 디자이너가 못 고칩니다 |
| 종류 구분 | 컴포넌트 / 인터페이스 | 태그 문자열, `name` 비교 | 오타가 컴파일에 안 걸립니다 |
| 배치·생성 | 디자이너가 씬에 놓은 것 | 런타임에 절차적으로 생성 | 프로젝트 전체 규칙입니다 |

## 5. 자주 밟는 함정 다섯

### ① 소유권 — "지금 이 자리를 누가 들고 있나"

같은 것을 둘이 동시에 건드리면 조용히 상쇄됩니다. 버그 중 제일 찾기 어려운 종류입니다.

- **위치**: 넉백 / 경직 중에는 AI가 이동하지 않습니다
- **조준**: 플레이어 쪽은 `PlayerActionState`가 "지금 조준을 누가 들고 있나"를 중재합니다

새 기능이 **위치나 회전을 직접 건드린다면**, 먼저 "이미 그걸 건드리는 다른 것이 있나"를 찾으세요.

### ② 타이머는 전부 `Time.time` 기준입니다

```csharp
_readyAt[index] = Time.time + attack.Cooldown;   // 언제 다시 쓸 수 있나
if (Time.time < _readyAt[index]) continue;       // 아직이면 건너뛴다
```

"남은 시간을 매 프레임 깎는" 방식이 아니라 **"언제 끝나는가"를 적어두는** 방식입니다.
전자는 프레임이 끊기면 값이 틀어지고, 멈춤 처리를 넣을 때 깎는 자리를 전부 찾아야 합니다.

> ⚠️ 곧 바뀝니다. 기획이 "창을 열면 적의 행동과 버프 시간이 멈춘다"를 요구해서
> `Time.timeScale = 0`을 넣을 예정입니다. 그러면 `Time.time`은 멈추지만
> `Time.unscaledTime`은 계속 흐릅니다. **연출(UI)은 `unscaled`, 게임 로직은 그냥 `Time.time`**으로 두세요.

### ③ "재사용 대기"와 "빈틈"은 다른 축입니다

헷갈리기 쉬운 두 값이 공격 에셋에 나란히 있습니다.

- **재사용 대기(`Cooldown`)** — *이 공격을* 다시 쓰기까지의 시간. 다른 공격은 그동안도 나갑니다.
- **빈틈(`Recovery`)** — 내지른 뒤 **이동도 다른 공격도 못 하는** 시간.

1구역의 "막거나 피하면 잠시 멈추니 반격할 수 있다"가 빈틈으로 성립합니다.
`StaggerWhenBlocked`는 방패에 막혔을 때 추가로 멈추는 시간이고, 0이면 빈틈과 같게 둡니다 —
막아낸 보람이 빈틈보다 짧으면 방패를 들 이유가 없어지기 때문입니다.

### ④ 재사용 대기는 공격마다 따로 돕니다

`MonsterAI`가 `float[] _readyAt`을 공격 개수만큼 들고 있습니다.
하나로 묶으면 근접을 쓴 뒤 투사체까지 같이 잠깁니다. 새 공격을 추가해도 이건 자동으로 따라옵니다.

### ⑤ 공격 **목록 순서**가 우선순위입니다

`PickAttack`은 쓸 수 있는 것 중 **목록에서 앞선 것**을 고릅니다.
우선순위를 코드에 적지 마세요 — 디자이너가 에셋 목록 순서로 정합니다.

## 6. 기획 메모에서 나온 설계 방침

읽으면서 정리해둔 것 중 **코드에 영향이 있는 것**만 옮깁니다.

### 스폰은 두 방식 다 만들어둡니다

기획서는 "지정된 위치에 스폰"이라 적혀 있지만 구두로는 다른 얘기가 나왔습니다.
**어느 쪽이 될지 모르므로 둘 다 만들어두고 에셋에서 고릅니다.**

- **배치 스폰** — 디자이너가 씬에 놓은 자리에서 생성
- **랜덤 스폰** — 구역 안의 지정 영역에서 빈 칸을 골라 생성

> 랜덤이라고 해서 **지형이나 오브젝트를 런타임에 만드는 것이 아닙니다.**
> 이미 있는 칸 중에서 **어디에 놓을지만** 고르는 것입니다. 이 구분이 중요합니다 —
> 프로젝트 규칙이 "런타임 절차적 생성 금지"이고, 위치 선택은 거기 해당하지 않습니다.

### 예고는 "읽히는 것"이 전부입니다

기획이 보스의 **3번째 패턴만** 방어 불가로 두고, 전조를 **붉은 바닥 범위 표시**로 정했습니다.

> 직접 적어둔 우려: *"소리, 색 등에서 차이점을 주는데 이거 처음에는 몰라서 무조건 맞을듯"*

맞는 지적이고, 코딩할 때 이렇게 대응합니다 — **방어 불가 공격은 예고 시간을 넉넉히 주고,
일반 공격과 색·소리·바닥 표시를 전부 다르게 합니다.** 하나만 다르면 못 읽습니다.
예고 시간은 당연히 에셋 값이라 플레이테스트에서 바로 늘릴 수 있어야 합니다.

구현 쪽에는 **`MonsterAI.Telegraphing` 이벤트**가 이미 있습니다.
예고가 시작될 때 "어떤 공격인지"와 함께 한 번 발생합니다.
연출(점멸·바닥 표시·소리)은 **이 이벤트를 듣는 쪽에서** 만듭니다 — AI가 연출을 직접 부르지 않습니다.

### 구역 점령 / 확보

- **점령 상태** = 몬스터가 나와 있는 상태
- **확보 상태** = 그 구역 몬스터를 전부 잡은 상태. 이때부터 광물이 생깁니다
- 확보한 구역의 일반 몬스터는 **다시 나오지 않습니다** (지금 코드의 "재등장 지연"과 충돌 — 바꿔야 합니다)
- 전투 중 **사망하거나 구역 밖으로 나가면 전원 원래 배치·체력으로 복원**됩니다

마지막 항목이 코딩에 영향이 큽니다. "다시 나온다"가 아니라 **"처음 상태로 되돌린다"**입니다.
그래서 몬스터를 지웠다 새로 만드는 게 아니라, **죽은 것도 살려서 제자리에 돌려놓는** 쪽이 맞습니다
(`Monster.Respawn()` / `ReturnHome()`이 그 용도로 이미 있습니다).

### 몬스터 처치에는 보상이 없습니다

골드도 광물도 경험치도 주지 않습니다. 경험치는 광물 파괴로만 얻습니다.
보상 코드는 이미 토글로 꺼져 있으니 **켜지 마세요.** 전투의 보상은 "구역 확보" 그 자체입니다.

## 7. 다 쓰고 나서 확인하는 법

이 프로젝트는 유닛 테스트 대신 **플레이 모드에서 실제 코드 경로를 태워 확인**합니다.
새 몬스터 행동을 짰으면 최소한 이것만은 눈으로 보세요.

1. **예고 → 공격이 실제로 그 시간만큼 걸리나** (초시계로 재보면 됩니다)
2. **예고 중에 피하면 안 맞나**
3. **예고 중에 때리면 끊기나** (경직)
4. **쿨다운이 다른 공격을 막지 않나**
5. **플레이어가 구역 밖에 있을 때 쫓아오지 않나**
6. **`Tools/ForagerCP/씬 검사` → 오류 0 / 경고 0**
7. **`Tools/ForagerCP/밸런스 표`에서 수치가 의도한 값인가**

6번은 커밋 전에 **반드시** 돌립니다. 배선 누락처럼 "돌려봐야 아는 문제"를 미리 잡아줍니다.

## 8. 커밋할 때

- **브랜치를 따지 않고 `main`에 바로 올립니다.** 유니티 에셋·씬은 깃이 자동으로
  합쳐주지 못하는 파일이라, 브랜치가 오래 살수록 나중에 손으로 풀 것이 늘어납니다.
  대신 **시작 전에 `git pull`**, 한 덩어리가 끝날 때마다 바로 올립니다.
- 커밋 메시지에 **무엇을 왜 그렇게 정했는지**를 적습니다.
  수치와 판정은 반드시 나중에 다시 건드리게 되고, 그때 "왜 이 값이었나"가 남아 있어야 합니다.
- **씬 파일(`Assets/Scenes/SampleScene.unity`)은 당분간 건드리지 마세요.**
  하나의 거대한 파일이라 두 사람이 같이 고치면 깃 충돌을 손으로 풀기가 매우 어렵습니다.
  배치가 필요하면 말해주세요.

## 9. 막히면

- **Create 메뉴에 새 에셋이 안 보인다** → 콘솔에 컴파일 오류가 있는지 먼저 봅니다
- **코드를 고쳤는데 반영이 안 된다** → 유니티가 컴파일 중일 수 있습니다. 우하단 회전 아이콘 확인
- **몬스터가 가만히 있는다** → `MonsterAI.Current`(지금 칸)를 인스펙터 Debug 모드나 로그로 찍어봅니다.
  경직 중이면 `Stagger`, 쿨다운 대기면 `CooldownWait`로 나옵니다. 칸이 바뀔 때마다 알고 싶으면
  `MonsterAI.StateChanged` 이벤트를 들으면 됩니다
- **"이걸 코드로 짜는 게 맞나" 싶다** → 0장의 질문으로 돌아갑니다. 대부분 에셋으로 끝납니다
- 그 외 전부 물어봐 주세요. 주석이 부족해서 막힌 것이면 주석 쪽을 고치겠습니다
