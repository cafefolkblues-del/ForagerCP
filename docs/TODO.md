# 할 일 우선순위

기준: 2026-10-16 기획서 2종(상점 상품 및 구매 / 1~5구역 몬스터 콘텐츠) + 2·3차 프로토타입 피드백.
명세와 코드의 차이는 [SPEC_SYNC.md](SPEC_SYNC.md), 여기는 **무엇을 어떤 순서로 하는가**만 적는다.

## 기획 확정 사항 (2026-10-16 확인)

| 항목 | 답 | 코드에 미치는 영향 |
|------|----|------|
| 도구 강화를 상점으로 옮기나 | **보류** — 기획서 간 충돌, 상의되지 않음 | 제작대·제작 시간·슬롯 큐 **그대로**. 상점 개편에서 도구 강화만 뺀다 |
| 광물 5종(돌·철·은·금·수정) | **확정** | 구리 → 돌로 개명(단가 10·체력 30으로 최하위라 자리가 맞는다), 은·금 신설 |
| 보스 소환 물품 | **열쇠** — 소모되지 않음 | 제단은 보유 검사만. 실패해도 그대로 |
| 예고 3개 이상 겹칠 때 | **미정** | 동시 예고 제한을 수치로 빼두고 0(제한 없음)으로 둔다 |
| 플레이어 체력 100 | **확정** — 단 2칸 하트가 먼저 확정됐던 이력이 있음 | 100 스케일로 가되 `HeartBarView`는 **지우지 않는다**. 되돌아올 수 있다 |
| 전투 목표 시간 vs 체력 | **체력이 맞다** | 몬스터 체력·피해는 문서 값 그대로. 목표 시간 표는 참고만 |

## P0 — 버그. 기획 답 없이 간다 ✅ 완료

- [x] **1. 드랍 복사**(3차-6). 바닥 드랍이 저장에 안 들어가고 불러올 때 치우지도 않아
      인벤만 롤백되고 드랍은 남는다 → 주우면 복사.
      **저장하지 않고 불러올 때 전량 회수**가 맞다. 수명 30초짜리를 저장할 가치가 없고,
      남겨두면 반드시 복사가 난다. `PlacedBlocks.ClearAll`과 같은 패턴.
- [x] **2. 불러오기 후 광물·캐릭터 끼임**(3차-5). 리스폰 코루틴은 점유를 보지만(`IsBlocked`)
      저장된 플레이어 위치를 되돌리는 쪽은 안 본다. 양쪽 다 막는다.
- [x] **3. 대시로 광물 관통**(3차-4). 플레이어 Rigidbody가 Discrete인데 대시가 2.2배속이라
      `MovePosition` 한 스텝이 1m 콜라이더를 건너뛴다. `ContinuousDynamic`으로.
- [x] **4. 투사체 방패 판정이 탄이 아니라 쏜 몬스터를 본다.** 기획이 "뒤에서 맞으면 피해"를
      명시했으므로 탄 위치를 넘겨야 한다.
- [x] **5. 차단벽 너머 어그로·공격**(3차-1). ⓐ 탐지에 시야 판정 ⓑ 자기 구역 밖 플레이어는
      표적 해제. ⓑ는 구역 점령(P3-21)에 어차피 필요하다.
      → **ⓑ만으로 끝났다.** 벽은 구역 경계에 서 있어서 '같은 구역인가'만 물으면 벽 너머가
      통째로 걸러진다. 시야 레이캐스트는 광물·구조물 뒤에 선 것까지 놓쳐 보고된 것보다
      넓게 바뀌므로 넣지 않았다.

> **P0에서 걸린 것 하나.** `MonsterAI`가 자기 구역을 `Start()`에서 잡으면 안 된다 —
> 스폰 자리는 같은 오브젝트의 `Monster.Start()`가 세우는데 같은 오브젝트 안의 Start 순서는
> 보장되지 않아 원점(0,0,0)의 구역을 본다. 값이 설 때까지 다시 묻는 지연 조회로 바꿨다.
> `SkillBoard.Awake` ↔ `PlayerLevel.Awake` 때와 같은 함정이다.

## P1 — C8 틀 마저. 확정된 스펙이라 답을 안 기다려도 된다 ✅ 완료

- [x] **6. `Recovery`(공격 후 빈틈).** 쿨다운과 별개 축. 돌무더기의 "막으면 멈추니 반격"이
      1구역 핵심 재미라 이게 없으면 1구역이 성립하지 않는다.
- [x] **7. `LungeAttack`(돌진).** 예고 1.0초 / 직선 최대 5m / 방향 전환 없음 / 벽에 닿으면 멈춤 /
      후방은 방어불가.
- [x] **8. 접촉 피해.** 코드에 `OnCollision` 계열이 0건인데 돌무더기·골렘이 전제로 깔고 있다.
- [x] **9. 투척꾼 후퇴.** `MinRange`로 안 쏘는 것까지는 되는데 물러나는 이동이 없다.
- [x] **10. 막혔을 때 공격자 경직.** `PlayerShield.Blocked` 이벤트가 이미 있다.
- [x] **11. 스폰 둘 다**(배치 / 랜덤). 랜덤은 **구역 안 지정 영역에서 칸을 고르는** 방식 —
      런타임에 지형을 만드는 게 아니라 배치 위치만 고르는 것이라 "절차적 생성 금지"에 안 걸린다.
      **씬에 구역당 하나씩 셋 올려뒀고 지금은 꺼둔 상태다**(`Spawner_Region_*`, 배치 모드 · 자리 3개).
      구역 점령(P3-21)이 켜는 주체가 되므로 그때까지는 꺼둔다.
      랜덤 범위는 각 구역의 가장 넓은 볼륨으로 미리 채워 두어 모드만 바꾸면 바로 돈다.

> **P1에서 바뀐 모양 두 가지.**
> - **접촉 피해를 물리 충돌이 아니라 공격 하나(`ContactAttack`)로 만들었다.** 수치·방패 판정·
>   재사용 대기를 다른 공격과 같은 자리에서 읽게 되고, 무엇보다 **빈틈 중에는 닿아도 안 들어간다**.
>   빈틈은 플레이어의 반격 창인데 거기서 몸통 피해가 계속 들어오면 붙어서 때릴 수가 없다.
> - **돌진은 이동을 직접 하지 않고 `MonsterAI.BeginLunge`에 부탁한다.** 위치를 쥐는 곳이 둘이 되면
>   넉백·경직과 누가 몸을 옮기는지가 흐려진다. 공격은 "이 방향으로 이만큼"만 말한다.
>
> 물러날 거리도 따로 두지 않고 공격의 `MinRange`에서 끌어낸다(`MonsterDefinition.RetreatRange`).
> 수치를 둘로 두면 "안 쏘는 거리"와 "물러나는 거리"가 어긋나 쏘지도 물러나지도 않는 구간이 생긴다.

## P2 — 플레이테스트 피드백. 작고 효과 크다

- [x] **12. 창 닫기**(3차-2). ESC→메뉴는 "편의성"으로 넣었는데 역효과라는 피드백.
      **창이 떠 있으면 ESC는 그냥 닫기**, 메뉴는 창이 없을 때만. 닫기 버튼 + 상호작용키 재입력도.
- [x] **13. 제작 재료 부족 표시**(3차-3). 지금 첫 번째 모자란 것 하나만 말한다.
      전 종류의 `필요/보유`를 항상. 상점 도구 강화 화면도 같은 요구다.
- [x] **14. 채광·공격 후딜 공유**(2차-1). 별도 타이머라 채광 직후 공격이 공짜로 나간다.
- [x] **15. 차지 표시**(3차-8). 확인 결과 채광 중엔 차지가 **안 된다**(`_harvestLock`).
      오해가 생긴 이유가 진짜 문제 — `ChargeRatioChanged` 구독자가 0명이라 화면에 안 보인다.
      → `ChargeBarView`로 붙였다. 핫바 바로 위 가운데 — 차지는 손이 하는 일이라 시선이
      가 있는 아래쪽에 둔다. 다 차면 색이 바뀐다.
- [ ] **16. 퀵슬롯 재배치**(3차-7). 보관함 패널의 칸 클릭 구조를 그대로 쓴다.
- [ ] **17. 못 줍는 곳까지 채광 가능**(2차-2). 의도면 그대로 둔다 — 캔 것이 바닥에 떨어져
      30초 뒤 사라지므로 손해는 없다. **확인만 필요.**

> **P2에서 남은 둘(15 차지 게이지 · 16 퀵슬롯 재배치)은 화면을 새로 지어야 한다.**
> 나머지 셋은 코드만으로 끝났다.
>
> 창 닫기는 **되돌린 결정**이다. "ESC로 닫으면 메뉴 표시"를 편의성으로 넣었는데,
> 메뉴를 거치지 않고 여는 창(상점·제작대·판매·보관함)이 훨씬 많아 돌아갈 곳 없는 메뉴가
> 뜨고 두 번 눌러야 했다. 상호작용키 재입력으로도 닫히는데, 판정은 **화면 쪽**이 한다 —
> "이미 내가 띄운 그 역인가"를 보므로 역은 자기 화면이 떠 있는지 몰라도 된다.
>
> 후딜 공유는 양방향이다. 캐다가 바로 못 베고, 베고 나서 0.4초는 못 캔다.
> `_shareActionCooldown`으로 끌 수 있다.

> **UI 리소스가 들어왔다**(`Assets/_Project/Art/UI/`, 32장). `stats/hp_line.png`(알약 테두리)
> + `stats/gauge.png`(채움) 한 쌍이 막대의 표준 모양이다. 늘어나는 조각은 9분할로 지정해
> 가로로 늘려도 둥근 끝이 안 납작해진다. 차지 막대가 이 쌍을 처음 쓴다.
>
> 테두리는 **어둡게** 둔다. 밝게 두면 노란 채움 위에서 선이 묻혀 그냥 알약 하나로 보인다.
>
> 체력·경험치 막대를 같은 쌍으로 갈아끼울지는 아직 안 정했다. 하트는 "확정이 뒤집힐 수
> 있으니 남겨두자"는 쪽이라 `HeartBarView`를 건드리지 않았다.

## P3 — 신규 시스템. 순서가 중요하다

- [ ] **18. 광물 5종 교체.** 먼저 와야 한다 — 도구 강화 재료·판매 단가·구역 배치가 전부 걸려 있다.
- [ ] **19. 수치 전면 교체.** 체력 100, 평타 10/13/17/22, 방어구 %, 회복 %, 버프 %, 채집력 1~5.
      **몬스터 에셋보다 먼저.** 안 그러면 두 번 적는다.
- [ ] **20. 몬스터 4종 + 구역 배치 에셋.** 여기부터는 코드가 아니라 에셋 작업이다.
      **범위: 종류 분리와 행동(공격 조합·수치)까지.** 모션은 아트가 나오면 그때 잇는다.
- [ ] **21. 구역 점령/확보 상태.** 잠김 → 점령 → 확보. 광물 생성이 여기 달린다.
      "광물은 저장 대상 제외"로 정한 것이 여기서 맞아떨어진다 — 광물 존재가 구역 상태에서
      파생되면 **구역 상태만 저장**하면 된다.
- [ ] **22. C9 경계 이탈·사망 → 전투 초기화.** 지금 `RegionTracker`는 들어오는 걸 막는다.
      나가는 걸 감지하는 반대 방향 기능이 필요하다.
- [ ] **23. 보스.** 패턴 3종 + 체력 50% 이하 간격 단축은 `MonsterAttack.CanUse(context)`에
      체력 비율만 얹으면 상속으로 끝난다.

## P4 — 상점 개편 (도구 강화 제외 — 보류 건)

- [ ] **24. 목록 표시 규칙.** 전부 보이되 비활성 + 이유. 지금은 숨긴다.
- [ ] **25. 소모품 수량 선택 구매.** `SpaceFor`가 이미 "전체 아니면 안 됨" 모양이라 얹힌다.
- [ ] **26. 소모품 4종.** 작은/큰 회복, 공격/채집 버프.
- [ ] **27. 이동 편의 영구 구매.**
- [ ] **28. 창 열면 시간 정지.** 넉백·대시·쿨다운·몬스터 예고가 전부 `Time.time` 기반이라
      한 번 훑어야 한다. `UiWindow`는 이미 `unscaledDeltaTime`이라 멀쩡하다.

## 기획에 물어볼 것

1. **"광물이 생성된다"가 랜덤 배치인가.** 상시 제약인 *런타임 절차적 생성 금지 / 디자이너가
   직접 배치*와 정면으로 부딪힌다. 몹 스폰을 둘 다 만들기로 했으니 광물도 같은 틀로 가면 되는지.
2. **전투 초기화에 로딩·연출을 두나.** 지금 설계는 그 자리에서 즉시 재배치라 순간이동처럼 보인다.
3. **가불기 첫 조우.** 처음엔 모르고 무조건 맞는다. 첫 사용만 예고를 길게 줄지, 맞고 배우는 게 의도인지.
4. **맵 크기.** 구역 하나가 "몹 전부 처치 → 광물 생성" 단위면 생각보다 작아진다.
   지금 구획해둔 3개 크기로 괜찮은지.
5. **예고 3개 이상 겹칠 때** 무엇을 흩는지(예고를 미루나, 접근을 늦추나).
6. **이동 편의 품목 / 판매 불가 광물 "등급" 목록 / 버프 수치 공식** — 이전부터 미결.
